Точки входа

Пять публичных доменов, один edge.

Каждый продукт получает свой домен и свой набор cookie/CORS правил. Один Nginx раздаёт TLS, статический кэш, CSP, rate-limits и ACME-сертификаты — и проксирует трафик в нужный gateway или origin.

Слои системы

Пять слоёв: от пользователя до диска.

Запрос проходит сверху вниз: продукт → edge → frontend/gateway → сервисы и воркеры → data plane. Никакой другой путь не разрешён: фронт не ходит в Postgres, сервис не ходит в чужой namespace, gateway не пробрасывает spoofed identity headers.

Маршрутизация

Два gateway, декларативный YAML.

Маршруты живут в gateway.yaml и gateway.artist.yaml. Каждый маршрут несёт policy class (public · auth_only · unsafe · stream · static), требование require_user, rate-limit и таймаут. Никаких inline-исключений в коде — только конфиг.

main · api-gateway

  • /api/auth · /api/profile · /api/verify → auth-service · class auth_only
  • /api/stream/v3/session → direct-stream-service · class unsafe · RL stream
  • /api/stream/v2/* → direct-stream-service · class stream
  • /audio/v3/* (GET/HEAD) → direct-stream-service · cookie-bound
  • /api/ebap-hls/v1/session → ebap-hls-adapter · RL stream

  • /api/artists · /api/albums → artist-service · cache catalog

Party Mode гарантии

  • Стабильный queueId — удаление по идентификатору, а не по индексу.
  • NACK обработка — backend reply {ok:false, code} доходит до UI как ошибка.
  • NATS JetStream — durable subscriptions, fanout по shard_count.
  • Redis DB2 — Lua-скрипты для атомарного add_to_queue / remove.
  • WS auth — short-lived PARTY_V2_WS_TOKEN с привязкой к пользователю.

Device Sync гарантии

  • Server-authoritative ownership — activeRevision монотонно растёт.
  • revoke_audio — server-only command, гасит выход у пассивных без локального override.
  • transfer · resume — новый активный получает nowPlaying и стартует output.
  • Stale-revision защита — UI игнорирует устаревшие события.
  • Suspend output — клиент останавливает sink, но не публикует pause наружу.

Безопасность и доверие

Безопасность — это фича продукта, не аддон.

Каждая граница доверия задокументирована и проверяется тестами: edge → gateway → внутренний service mesh → data plane. Артистский кабинет полностью изолирован от слушательской платформы — отдельный домен, cookie namespace, gateway-конфиг и MFA-политика.

Edge boundary

  • TLS 1.2+ Let's Encrypt · auto-renew + reload без даунтайма.
  • HSTS preload · 1 год · includeSubDomains.
  • CSP · strict default-src · отдельные политики для earflow / auth / artists / strmhaha.
  • CORS allowlist · никаких * · per-domain origin.
  • Rate / body limits · stream/cover/upload/auth zones.
  • Admin endpoints · только 127.0.0.1 на портах 8085 / 8443.

Gateway boundary

  • HttpOnly cookies · mp_sid/mp_csrf на listener; mp_sid_artists/mp_csrf_artists на artist.
  • CSRF на unsafe методах · HMAC sid.nonce с JWT_SECRET.
  • require_user / route policy · декларативно в YAML, не в коде.
  • Service tokens · короткоживущие JWT для service-to-service.
  • Identity header sanitation · spoofed X-User-* ломаются на входе, ставятся middleware.
  • Fail-closed · ошибка авторизации = 401, никогда не 200.

Auth & MFA

  • PBKDF2-SHA512 · 600k итераций · auth-service + security-service.
  • MFA TOTP + recovery codes · обязательный для артистов.
  • Step-up · подтверждение для опасных операций (трек upload, password change, telegram unlink).
  • Session resilience · backend возвращает recoverable + reauthRequired; UI держит DEGRADED state, не дропает юзера.
  • Refresh rotation · /api/auth/refresh с binding на UA/IP hash.

Data & supply chain

  • Postgres · только internal Docker network, без публичных портов.
  • Redis-auth · отдельный инстанс, noeviction, без auto-deletion sessions при rotateStatusInvalid.
  • MinIO · localhost-only консоль, anonymous=none на audio/EBAP buckets.
  • Pinned images · MinIO/Postgres/Redis/Meili/NATS закреплены SHA-релизами.
  • Secrets · только .env + secret manager, не в git.

Развёртывание и масштаб

Production — это один docker compose up.

Платформа разворачивается одним docker-compose.yml: pinned образы, healthchecks, security hardening (read-only fs, no-new-privileges, resource limits), масштабируемый api-gateway за Nginx, Let's Encrypt с авто-перезагрузкой и tools-профиль для тестов и миграций.

Compose topology

  • nginx · music-nginx-lb:hardened · 80/443 публично, 8085/8443 на 127.0.0.1.
  • api-gateway · replicas 2 по умолчанию (API_GATEWAY_REPLICAS), 0.5 cpu / 512 MB на инстанс.
  • artist-api-gateway · отдельный контейнер с gateway.artist.yaml.
  • frontend / artist-frontend · production-сборки, read-only rootfs + tmpfs.
  • certbot + cert-reloader · ACME-renew + inotify SIGHUP, без даунтайма.
  • tools profile · pgadmin, integration-tests, upload-service-tests, reco-feedback-loadgen.

Resilience controls

  • healthcheck на каждом сервисе · 30s/5s/3 retries.
  • graceful shutdown · SIGTERM в Go-сервисах + draining inflight requests.
  • resource limits · cpu/memory limits + reservations.
  • read-only fs + tmpfs · большинство Bun/Go контейнеров.
  • backups · scripts/backup-postgres.sh, backup-minio.sh, ./backups/.
  • monitoring overlay · отдельный docker-compose.monitoring.yml.

Стек · версии · планы

На чём стоит и куда идёт.

Стек подобран по принципу: каждый язык — на своей задаче. Go держит сетевые границы и hot-path, Bun — низкоуровневую работу с медиа, Node — бизнес-логику и интеграции, React — UI. Версии прибиты, обновления выкатываются в monitoring overlay.

Стек платформы

  • Go 1.22+ · gateway · party · device-sync · security · ranking · reco-feedback
  • Node.js 22+ · auth · database · artist · playlist · upload · subscription · search · lyrics · recommendations · transcode · metadata · import
  • Bun · direct-stream · ebap-hls-adapter · ebap-encoder · ebap-hls-packager
  • Python 3 · audio-features-worker (librosa-style features)
  • React 18 · frontend (CRACO + splitChunks) · artist-frontend
  • Nginx · TLS, cache, маршрутизация, security headers
  • Docker Compose · единый production runtime
  • Telegram Auth · только как identity для входа, без UI-зависимостей
